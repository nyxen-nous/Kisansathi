# AZINHACK ’26 submission readiness checklist

Use this as a final gate; checked items should have evidence.

## 20 points — Working GitHub project
- [ ] Repository is public and opens when signed out.
- [ ] README has correct setup instructions and no fake team names, stale test counts or secrets.
- [ ] A clean install/launch was tested on the submission machine.
- [ ] The core Farmer Support workflow works in the actual browser.
- [ ] The README, source and current demo agree about the feature state.

## 20 points — TinyFish integration
- [ ] `TINYFISH_API_KEY` configured locally, never committed or shown on video.
- [ ] A real TinyFish Search request completed successfully.
- [ ] A real TinyFish Fetch request completed successfully.
- [ ] Source URLs open and remain within the approved government-domain boundary.
- [ ] The video shows the live result and explains why Search + Fetch are useful.
- [ ] Missing/incomplete fields are described honestly; no static mock is passed off as live.

## 10 points — Social media
- [ ] Public post is published.
- [ ] It explains what the project does and who it helps.
- [ ] Includes a real GitHub link and preferably a short demo/screenshot.
- [ ] Judges can open it while signed out.

## 10 points — Technique
- [ ] Backend tests rerun successfully.
- [ ] JavaScript syntax checks pass.
- [ ] API key stays server-side.
- [ ] Failure states and partial results are shown gracefully.
- [ ] The team can explain validations, error handling and remaining limitations.

## 20 points — Innovation and idea
- [ ] Pitch leads with a specific farmer problem rather than a long feature list.
- [ ] TinyFish’s value is clear and not token-only integration.
- [ ] Claims about novelty and impact are evidence-based.
- [ ] Team can show genuine contribution and event-specific work.

## 10 points — Impact and usefulness
- [ ] Demo explains a realistic farmer task.
- [ ] Official links and uncertainty notes are visible.
- [ ] No unsupported eligibility, savings, accuracy or adoption claims.

## 10 points — Demo video and explanation
- [ ] 2–3 minute walkthrough submitted.
- [ ] Live workflow is readable, paced and narrated.
- [ ] No secrets or private data visible.
- [ ] Video link is accessible to judges.

## Eligibility and required artefacts
- [ ] Public GitHub repo.
- [ ] Public social post.
- [ ] Demo video.
- [ ] PPT uploaded to the event portal.
- [ ] Actual team names/contributions verified.
- [ ] Organisers have confirmed the pre-existing-project policy if applicable.
